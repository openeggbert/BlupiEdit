BLP File Format

Complete binary specification of the .blp level file format used by Speedy Blupi II.

⚠

This specification was derived by reverse engineering. Fields marked "Unknown" have not been fully mapped. All multi-byte values are little-endian.

Overview

A .blp level file is a flat binary structure with no headers, magic bytes, or compression. Fields are read by seeking to hard-coded byte offsets. The file contains:

  • Version information
  • Level metadata (scroll, music, background)
  • Up to 4 player start positions and directions
  • A 40-character level name
  • Two 100×100 tile grids (layers)
  • Up to 200 game object (item) records

Header — Offset 0x00

The file begins with a two-field version record:

OffsetSizeFieldTypeDescription
0x002 BMajorVersionuint16Major format version number
0x022 BMinorVersionuint16Minor format version number
0x04–0xD3208 BUnknown gapNot read by BlupiEdit (may contain additional metadata)
 
// Reading in LevelData constructor
MajorVersion = reader.ReadUInt16();  // @ 0x00
MinorVersion = reader.ReadUInt16();  // @ 0x02

Scroll Flags — Offset 0xD4

OffsetSizeFieldTypeDescription
0xD44 BHorizontalScrollint32100 = scroll enabled, 0 = disabled
0xD84 BVerticalScrollint32100 = scroll enabled, 0 = disabled
 
str.Seek(0xD4, SeekOrigin.Begin);
HorizontalScroll = reader.ReadInt32() == 100;  // true if value is 100
VerticalScroll   = reader.ReadInt32() == 100;
ℹ

The scroll value is stored as an integer (100 = on) rather than a boolean. This suggests it may originally have been a scroll speed percentage. Only 0 and 100 appear in practice.

Music & Background — Offset 0xDC

OffsetSizeFieldTypeDescription
0xDC2 BskipSkipped (unknown)
0xDE2 BMusicint16Music track index
0xE02 BBackgroundint16Background index N → loads decor{N:000}.blp
 
str.Seek(2, SeekOrigin.Current);  // skip 2 unknown bytes @ 0xDC
Music      = reader.ReadInt16();    // @ 0xDE
Background = reader.ReadInt16();    // @ 0xE0

Start Positions — Offset 0x148

Four player start positions are stored as world-space pixel coordinates, followed by four direction flags.

OffsetSizeFieldTypeDescription
0x1488 BStartPositions[0]int32 × 2Player 1 — X, Y in pixels
0x1508 BStartPositions[1]int32 × 2Player 2 — X, Y
0x1588 BStartPositions[2]int32 × 2Player 3 — X, Y
0x1608 BStartPositions[3]int32 × 2Player 4 — X, Y
0x1684 BStartDirections[0]int32Player 1 — non-zero = facing right
0x16C4 BStartDirections[1]int32Player 2
0x1704 BStartDirections[2]int32Player 3
0x1744 BStartDirections[3]int32Player 4
 
str.Seek(0x148, SeekOrigin.Begin);
StartPositions = new Point[4];
for (int i = 0; i < 4; i++)
    StartPositions[i] = new Point(reader.ReadInt32(), reader.ReadInt32());

StartDirections = new bool[4];
for (int i = 0; i < 4; i++)
    StartDirections[i] = reader.ReadInt32() != 0;

Level Name — Offset 0x178

OffsetSizeFieldDescription
0x17840 BLevelNameNull-terminated string in Windows-1252 (CP1252), padded with zeros to 40 bytes
 
LevelName = reader.ReadString(40);  // custom extension method; stops at first null byte

Primary Tile Grid — Offset 0x364

A 100×100 array of int16 tile indices. The index references an entry in the Object sprite sheet. Value -1 means the cell is empty (no tile).

OffsetSizeFieldDescription
0x36420,000 BTiles[x, y]Primary tile grid; iterated x = 0..99, y = 0..99 (x-major order)
 
str.Seek(0x364, SeekOrigin.Begin);
Tiles = new short[100, 100];
for (int x = 0; x < 100; x++)
    for (int y = 0; y < 100; y++)
        Tiles[x, y] = reader.ReadInt16();
ℹ

Iteration order is x-major (all Y values for X=0 first, then X=1, etc.). This matches column-major storage. Cells with value -1 are skipped during rendering.

Secondary Tile Grid — Offset 0x4CB4

Identical structure to the primary tile grid. Purpose is not fully documented — it may represent a foreground/overlay layer or a second pass of tiles.

OffsetSizeFieldDescription
0x4CB420,000 BTiles2[x, y]Secondary tile layer; same layout as Tiles
 
// Reads immediately after Tiles (no seek needed)
Tiles2 = new short[100, 100];
for (int x = 0; x < 100; x++)
    for (int y = 0; y < 100; y++)
        Tiles2[x, y] = reader.ReadInt16();

Items Array — Offset 0x6404

An array of exactly 200 item records, each 48 bytes. Items with Type == 0 (None) are ignored when loading (not added to the Items list). When saving, unused slots are written as zero bytes.

OffsetSizeDescription
0x640448 BItem slot 0
0x643448 BItem slot 1
………
0x6404 + 199×4848 BItem slot 199
Total9,600 BFixed-size block regardless of actual item count
 
Items = new List<LevelItem>();
for (int i = 0; i < 200; i++)
{
    LevelItem item = new LevelItem(reader);
    if (item.Type != ItemTypes.None)
        Items.Add(item);
}

Saving items

for (int i = 0; i < Items.Count; i++)
    Items[i].Write(writer);
if (Items.Count < 200)
    writer.Write(new byte[0x30 * (200 - Items.Count)]);  // pad unused slots

Item Record Structure (48 bytes)

Each item record is read sequentially. See Architecture → LevelItem for the field table. Here is the exact read order:

ItemTypes Type  = (ItemTypes)reader.ReadUInt16(); // 0x00
ushort ABTime   = reader.ReadUInt16();               // 0x02
ushort BATime   = reader.ReadUInt16();               // 0x04
ushort AWait    = reader.ReadUInt16();               // 0x06
ushort BWait    = reader.ReadUInt16();               // 0x08
ushort field_A  = reader.ReadUInt16();               // 0x0A
Point  PointA   = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x0C
Point  PointB   = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x14
Point  PointC   = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x1C
ushort field_24 = reader.ReadUInt16();               // 0x24
ushort field_26 = reader.ReadUInt16();               // 0x26
ushort field_28 = reader.ReadUInt16();               // 0x28
TileTypes ArtFile = (TileTypes)reader.ReadUInt16(); // 0x2A
ushort Tile     = reader.ReadUInt16();               // 0x2C
ushort field_2E = reader.ReadUInt16();               // 0x2E

String Encoding

All strings in .blp files are encoded in Windows-1252 (CP1252) — a single-byte Western European encoding. This was the standard for Windows applications in the late 1990s when Speedy Blupi II was released.

// The encoding is a static singleton in LevelData
static readonly Encoding encoding = Encoding.GetEncoding(1252);

// ReadString extension — reads exactly <length> bytes,
// returns string up to first null byte
public static string ReadString(this BinaryReader br, int length)
{
    byte[] buffer = br.ReadBytes(length);
    for (int i = 0; i < length; i++)
        if (buffer[i] == 0)
            return LevelData.Encoding.GetString(buffer, 0, i);
    return LevelData.Encoding.GetString(buffer);
}

Level File Paths

Level files follow a predictable naming convention inside the game's data/ directory:

Level setPath patternCount
World (userid=0)data/world{N:000}.blp1–399
User 1–8 (userid=1..8)data/u{userid:000}-{N:000}.blp1–20 per user
 
public static string GetLevelName(int userid, int levelnum)
{
    if (userid != 0)
        return FindPathCaseInsensitive(GamePath("data",
            string.Format("u{0:000}-{1:000}.blp", userid, levelnum)));
    else
        return FindPathCaseInsensitive(GamePath("data",
            string.Format("world{0:000}.blp", levelnum)));
}
