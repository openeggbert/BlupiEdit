Contributing

This guide covers everything needed to build BlupiEdit from source, run it locally, and submit contributions back to the project.

Clone and Build

Clone the repository

git clone https://github.com/openeggbert/BlupiEdit.git
cd BlupiEdit

Build on Windows (Visual Studio)

  1. Open BlupiEdit.sln in Visual Studio
  2. Select the Debug or Release configuration from the toolbar
  3. Press Ctrl+Shift+B or choose Build → Build Solution
  4. The output binary is at BlupiEdit/bin/Debug/BlupiEdit.exe (or Release/)
# Or via MSBuild on the command line:
msbuild BlupiEdit.sln /p:Configuration=Release

Build and run on Linux (Mono)

# Install Mono (Debian/Ubuntu)
sudo apt install mono-complete

# Build with xbuild / msbuild
msbuild BlupiEdit.sln /p:Configuration=Release

# Run
mono BlupiEdit/bin/Release/BlupiEdit.exe /path/to/BLUPI.EXE
⚠

WinForms rendering under Mono may differ from native Windows. Some visual elements (font metrics, control sizing) may appear slightly different. These are known Mono quirks and are not bugs in BlupiEdit itself.

Code Style

There is no explicit style guide. The codebase follows the conventions visible in the existing code:

  • Naming: PascalCase for types and public members; camelCase for local variables and parameters
  • Braces: Allman style (opening brace on its own line)
  • Regions: Not used — keep methods in logical order without #region
  • Comments: Minimal inline comments; prefer self-documenting names
  • Line endings: CRLF (Windows default); the .gitattributes file normalises these on commit
  • Encoding: UTF-8 with BOM (Visual Studio default for C# files)
ℹ

When in doubt, match the style of the surrounding code. Consistency within a file matters more than adherence to any particular external style guide.

Testing

There is currently no automated test suite. Manual testing against the original game is the only option:

  1. Obtain BLUPI.EXE from a legal copy of Speedy Blupi II
  2. Run BlupiEdit and open the EXE — tile graphics should load without errors
  3. Open several World and User levels — the tile grid and objects should render correctly
  4. Save a level to a User slot and verify the .blp file was written correctly by reloading it in BlupiEdit. For binary verification, check the file size — a valid .blp file is always exactly 50,468 bytes (0xC524). You can also use a hex editor to spot-check known offsets: MajorVersion at 0x0000 should read 02 00, and the level name at 0x0178 should match what you set.
  5. Test on Linux with Mono if your change touches file paths or binary I/O

Contributing to the Documentation

The documentation lives in the web/ directory as static HTML files. If you add a new section, fix an error, or document a previously unknown field, follow these steps:

  1. Edit the relevant .html file in web/. Give every new section heading an id attribute (lowercase, hyphenated) so it appears in the auto-generated sidebar TOC and can be deep-linked.
  2. Add a corresponding entry to SEARCH_INDEX in web/js/main.js. The format is: 
    { title:'Short Title', desc:'keywords and phrases users might search', page:'page.html#anchor', section:'section-key' },
    The section key groups results (e.g. 'format', 'tiles', 'items', 'classes'). Omitting or getting this wrong means the section will not appear in search results.
  3. If your change adds a new top-level page, also update the <nav> and <footer> on every existing page. A Python one-liner can do this in bulk — see the approach used in the session history.
  4. Verify that the page renders correctly by opening it in a browser. Check that the sidebar TOC auto-populates your new headings and that the search finds your new entry.

Submitting a Pull Request

  1. Fork the repository on GitHub
  2. Create a feature branch: git checkout -b my-feature
  3. Make your changes; test manually as described above
  4. Commit with a clear message describing the change and its motivation
  5. Push to your fork and open a Pull Request against the master branch
git checkout -b fix/scrollbar-overflow
# make changes
git add BlupiEdit/MainForm.cs
git commit -m "Fix vertical scrollbar overflow when level is exactly 100 tiles tall"
git push origin fix/scrollbar-overflow

Please include a brief description of what was changed and why in the PR body. If the change is non-trivial, mention how you tested it. For bug reports or feature requests without a ready fix, open a GitHub Issue instead.
