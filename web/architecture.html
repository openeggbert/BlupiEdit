Architecture

A detailed walkthrough of the code structure, class responsibilities, and data flows in BlupiEdit.

Architecture Overview

BlupiEdit is a single-tier Windows Forms desktop application. It does not use MVVM or MVC in a strict sense — presentation logic lives in MainForm, while the data layer is encapsulated in the static class LevelData.

MainForm

File: BlupiEdit/MainForm.cs

The main application window. It hosts two custom-drawn panels (tilePanel and objectPanel), four scroll bars, a TileList, a PropertyGrid, and a MenuStrip.

Key fields

userid int private
Index of the currently loaded user collection. 0 = World levels, 1–8 = User collections.
levelnum int private
Number of the currently active level (1–399 for World, 1–20 for User).
selectedItem LevelItem private
The game object currently selected in the Object Panel. null when nothing is selected; PropertyGrid reverts to LevelViewModel.

Key methods

LoadGame(string filename)void
Delegates to LevelData.LoadGame(). Enables the Change Level menu item on success.
RefreshCurrentLevelView()void
Central refresh called after level load or panel resize. Configures all four scroll bars, repopulates TileList, assigns LevelViewModel to the grid, and invalidates both panels.
tilePanel_Paint(PaintEventArgs e)void
Renders: tiled parallax background (at ½ scroll speed), the visible portion of the 100×100 tile grid (with culling), Blupi's start position sprite, and all LevelItem sprites.
objectPanel_Paint(PaintEventArgs e)void
Renders the tiled background and all LevelItem sprites. The selected item is outlined with a yellow rectangle drawn over the sprite bounds.
objectPanel_MouseClick(MouseEventArgs e)void
Finds the nearest LevelItem within GridSize² pixels (Euclidean distance). Updates selectedItem and the PropertyGrid selection.

Rendering — culling optimisation

tilePanel_Paint does not redraw the entire level — only the visible tile range:

int xStart = Math.Max(scrollX / LevelData.GridSize, 0);
int yStart = Math.Max(scrollY / LevelData.GridSize, 0);
int xEnd   = Math.Min((scrollX + tilePanel.Width)  / LevelData.GridSize + 1, LevelData.LevelSize);
int yEnd   = Math.Min((scrollY + tilePanel.Height) / LevelData.GridSize + 1, LevelData.LevelSize);

for (int ty = yStart; ty < yEnd; ty++)
    for (int tx = xStart; tx < xEnd; tx++)
    {
        short tileIdx = level.Tiles[tx, ty];
        if (tileIdx < 0 || tileIdx >= objSprites.Length) continue;
        gfx.DrawSprite(objSprites[tileIdx],
            new Point(tx * LevelData.GridSize - scrollX,
                       ty * LevelData.GridSize - scrollY));
    }

LevelData

File: BlupiEdit/LevelData.cs

A hybrid class — acts as both an instance (data for one level) and a static container for shared game state (loaded graphics, EXE path). This is a deliberate design trade-off: it keeps the code simple at the cost of limiting the app to one game/level at a time.

LevelItem

File: BlupiEdit/LevelData.cs

Represents a single interactive game object in the level — an enemy, collectible, platform, or special effect. Each instance is exactly 48 bytes (0x30) in the binary file. Up to 200 items can be stored; items with Type == ItemTypes.None are skipped when reading.

Binary structure (48 bytes per item)

OffsetSizeFieldTypeDescription
0x002 BTypeItemTypesObject type (ushort enum)
0x022 BABTimeushortMovement time from A to B (game ticks)
0x042 BBATimeushortMovement time from B to A (game ticks)
0x062 BAWaitushortWait time at point A (game ticks)
0x082 BBWaitushortWait time at point B (game ticks)
0x0A2 Bfield_AushortUnknown (likely flags)
0x0C8 BPointAPointWorld position / start point A (two int32)
0x148 BPointBPointTarget movement point B
0x1C8 BPointCPointThird control point (purpose unknown)
0x242 Bfield_24ushortUnknown
0x262 Bfield_26ushortUnknown
0x282 Bfield_28ushortUnknown
0x2A2 BArtFileTileTypesSprite sheet to use (enum)
0x2C2 BTileushortSprite index within ArtFile sheet
0x2E2 Bfield_2EushortUnknown (padding?)

Computed speed properties

ABSpeed and BASpeed are derived from distance and time — they exist purely for convenience in the PropertyGrid:

// pixels per tick
public int ABSpeed {
    get => (int)Math.Round(LevelData.Distance(PointA, PointB) / ABTime);
    set => ABTime = (ushort)Math.Round(LevelData.Distance(PointA, PointB) / value);
}

TileList (UserControl)

File: BlupiEdit/TileList.cs

A custom scrollable tile-picker control. Supports horizontal and vertical layout modes, keyboard navigation, selection highlight, and drag detection.

Key properties

SelectedIndexint
Selected tile index (−1 = none). The setter scrolls the list to keep the selection visible and invalidates the control.
ImageSizeintdefault: 8
Rendered sprite size in pixels. The actual slot size is ImageSize + 4 (2 px padding on each side).
DirectionDirection enum
Layout direction: Horizontal or Vertical. Toggling hides/shows the appropriate scrollbar and recomputes the tile grid.
ImagesList<Bitmap>
The list of bitmaps to display. Call Images.Clear() and then Images.Add() to repopulate.

Events

  • SelectedIndexChanged — fires on click or keyboard navigation
  • ItemDrag — fires when the user starts dragging a tile

LevelSelectForm

File: BlupiEdit/LevelSelectForm.cs

A modal dialog for browsing and selecting levels. Operates in two modes controlled by LevelSelectFormMode:

  • Open — choose a level to load; button label is "Open" (or "New" for non-existent slots)
  • Save — choose a slot to save into; button label is "Save"

Behaviour

  • Discovers up to 8 user collections via info001.blp–info008.blp
  • World levels: up to 399; User collections: up to 20 each
  • On level selection, renders a 512×512 px miniature (8×8 grid tiles) centred on Blupi's start position
  • NumericUpDown allows direct entry of a level number

Output properties

  • UserID — 0 (World) or 1–8 (User)
  • LevelNum — level number from the NumericUpDown

Extensions (static class)

Data Flow — EXE Graphic Extraction

Tile graphics are embedded in BLUPI.EXE at hard-coded offsets. LevelData.LoadGame() reads them in this order:

// Fixed offsets in BLUPI.EXE (Speedy Blupi II)
BLUPI_TILES   @ 0x862F0  → TileInfo[] → TileTypes.Blupi000–003
OBJECT_TILES  @ 0x872B8  → TileInfo[] → TileTypes.Object
ELEMENT_TILES @ 0x88768  → TileInfo[] → TileTypes.Element
EXPLO_TILES   @ 0x894F8  → TileInfo[] → TileTypes.Explo

// For each TileTypes group:
using (Bitmap sheet = LoadImage("blupi000"))         // IMAGE16/ preferred
    foreach (TileInfo t in BlupiTiles)
        sprites.Add(new Sprite(sheet.Clone(t.Location, sheet.PixelFormat), t.Offset));
// sheet is disposed; only individual Sprite bitmaps remain in RAM
⚠

These offsets are specific to the original Speedy Blupi II binary. Other versions, patches, or mods may use different offsets.

Memory Management

BlupiEdit keeps all loaded sprites in memory for the entire application lifetime. Approximate RAM usage depends on sprite sheet resolution:

  • Blupi sprites (blupi000–003): 4 sets × N sprites — individual Bitmaps of ~1–20 KB each
  • Object tiles: the largest set; environment tiles for the 100×100 grid
  • Element tiles: environment decoration elements
  • Explo tiles: explosion animation frames
ℹ

LoadGame() calls bmp.Clone() for every sprite and immediately disposes the full sprite sheet (using block). Only small individual Bitmap objects remain in memory, one per sprite slot.
