Item Types

Complete reference for LevelItem and the ItemTypes enum — every game object that can appear in a Speedy Blupi II level.

ℹ

The .blp file stores up to 200 item slots (each exactly 48 bytes). Any slot whose first uint16 is 0 (ItemTypes.None) is treated as empty and is never loaded into the Items list. See BLP Format → Items Array for the full in-file layout.

Overview

All items share the same 48-byte LevelItem structure, serialised to/from the .blp file. The Type field determines how the game engine interprets the remaining fields — fields that are unused for a given item type are ignored at runtime but are still present in the binary record.

Items fall into five broad categories:

  • Platforms & Vehicles — moving objects Blupi can ride or interact with
  • Enemies — hostile objects that kill or damage Blupi on contact
  • Collectibles & Power-ups — items Blupi can pick up
  • Hazards & Explosives — stationary or autonomous danger zones
  • Special / Effects — goals, spawners, decorative animations

LevelItem Binary Layout (48 bytes)

File: BlupiEdit/LevelData.cs

Each LevelItem record is exactly 48 bytes = 0x30 bytes. All multi-byte fields are little-endian. Offsets are relative to the start of the record.

Rel. offsetSizeCLR typePropertyDescription
0x002uint16Type Object type; cast to ItemTypes. 0 = empty slot (never loaded into Items list).
0x022uint16ABTime Game ticks to travel from PointA to PointB.
0x042uint16BATime Game ticks to travel from PointB back to PointA.
0x062uint16AWait Pause ticks at PointA before starting the A→B journey.
0x082uint16BWait Pause ticks at PointB before starting the B→A return journey.
0x0A2uint16field_A Unknown. Read and preserved on save; purpose undocumented.
0x0C4int32PointA.X World pixel X of point A (item's primary position / spawn point).
0x104int32PointA.Y World pixel Y of point A.
0x144int32PointB.X World pixel X of point B (movement destination / patrol end).
0x184int32PointB.Y World pixel Y of point B.
0x1C4int32PointC.X World pixel X of point C. Purpose unclear; possibly a third control point or spawn origin.
0x204int32PointC.Y World pixel Y of point C.
0x242uint16field_24 Unknown.
0x262uint16field_26 Unknown.
0x282uint16field_28 Unknown.
0x2A2uint16ArtFile Which sprite sheet to use; cast to TileTypes. Determines which TileImages entry is used for rendering.
0x2C2uint16Tile Sprite index within the ArtFile sheet. Must be < TileImages[ArtFile].Length.
0x2E2uint16field_2E Unknown. Final 2 bytes of the 48-byte record.

Total: 2+2+2+2+2+2 + 4+4+4+4+4+4 + 2+2+2+2+2+2 = 12 + 24 + 12 = 48 bytes.

ℹ

Unknown fields (field_A, field_24, field_26, field_28, field_2E) are read from the file and round-trip preserved on save. They were not reverse-engineered. They may hold additional per-item-type data used by the game engine (e.g., initial state flags, sub-type parameters). Values from original game levels should not be destroyed on save.

Serialisation read/write code:

public LevelItem(BinaryReader reader)
{
    Type    = (ItemTypes)reader.ReadUInt16();    // 0x00
    ABTime  = reader.ReadUInt16();                 // 0x02
    BATime  = reader.ReadUInt16();                 // 0x04
    AWait   = reader.ReadUInt16();                 // 0x06
    BWait   = reader.ReadUInt16();                 // 0x08
    field_A = reader.ReadUInt16();                 // 0x0A
    PointA  = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x0C–0x13
    PointB  = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x14–0x1B
    PointC  = new Point(reader.ReadInt32(), reader.ReadInt32()); // 0x1C–0x23
    field_24 = reader.ReadUInt16();                // 0x24
    field_26 = reader.ReadUInt16();                // 0x26
    field_28 = reader.ReadUInt16();                // 0x28
    ArtFile  = (TileTypes)reader.ReadUInt16();   // 0x2A
    Tile     = reader.ReadUInt16();                // 0x2C
    field_2E = reader.ReadUInt16();                // 0x2E
}

⚠

If a level file contains an item with an unknown Type value, LevelData still loads it into the Items list (since the only check is item.Type != ItemTypes.None). The renderer will attempt to look up TileImages[item.ArtFile] — if valid, the sprite will draw. The game engine's response to unknown item types is undefined.

Most enemies use PointA and PointB as patrol boundaries. Contact with Blupi typically triggers death or damage. Notes:

  • Bulldozer (4) and Jeep (19) — ground patrol between PointA/PointB. Jeep is faster.
  • Fish (17) — semi-aquatic; jumps out of a water surface toward Blupi.
  • Bird (20) and Wasp (44) — airborne. Bird follows horizontal path; Wasp dives.
  • HeliportedEnemy (32) — initially carried by a helicopter; dropped onto the level and then patrols.
  • StuckEnemy (34) — stationary; attacks within a fixed radius rather than moving.

Item Movement System

All mobile items share the same A↔B timing architecture. BlupiEdit stores the timing parameters; the game engine performs the actual interpolation at runtime. The state machine is:

// Conceptual movement state machine (game engine — not in BlupiEdit)

State: WaitA
    Wait AWait ticks at PointA
    → transition to MoveToB

State: MoveToB
    Interpolate position from PointA → PointB over ABTime ticks
    Position = Lerp(PointA, PointB, ticksElapsed / ABTime)
    → when ticksElapsed == ABTime, transition to WaitB

State: WaitB
    Wait BWait ticks at PointB
    → transition to MoveToA

State: MoveToA
    Interpolate position from PointB → PointA over BATime ticks
    Position = Lerp(PointB, PointA, ticksElapsed / BATime)
    → when ticksElapsed == BATime, transition to WaitA

Loop forever.

Visual diagram:

PointA ──AWait──▶ [move to B over ABTime] ──▶ PointB ──BWait──▶ [move to A over BATime] ──▶ PointA ──▶ ...

Computed Speed Properties

LevelItem exposes two computed properties that convert between time and speed. These are useful for level editors that prefer to display speed in pixels-per-tick rather than raw tick counts:

// pixels per game tick (Euclidean distance / time)
[DisplayName("A to B speed")]
public int ABSpeed
{
    get { return (int)Math.Round(LevelData.Distance(PointA, PointB) / ABTime); }
    set { ABTime = (ushort)Math.Round(LevelData.Distance(PointA, PointB) / value); }
}

[DisplayName("B to A speed")]
public int BASpeed
{
    get { return (int)Math.Round(LevelData.Distance(PointB, PointA) / BATime); }
    set { BATime = (ushort)Math.Round(LevelData.Distance(PointB, PointA) / value); }
}

// Euclidean (straight-line) distance between two world points
public static double Distance(Point p1, Point p2)
    => Math.Sqrt(Math.Pow(p2.X - p1.X, 2) + Math.Pow(p2.Y - p1.Y, 2));
⚠

If ABTime == 0, reading ABSpeed causes a division by zero. Similarly, if PointA == PointB, the distance is 0 and speed is meaningless. BlupiEdit does not guard against this — avoid setting both points to the same location for moving items.

200-Slot Limit

The .blp file always stores exactly 200 item records (slots), regardless of how many are actually used. Unused slots are written as 48 zero bytes by Save():

// From LevelData.Save()
for (int i = 0; i < Items.Count; i++)
    Items[i].Write(writer);

// Pad remaining slots with zeros (Type = 0 = None)
if (Items.Count < 200)
    writer.Write(new byte[0x30 * (200 - Items.Count)]);

On load, all 200 slots are read. A slot is added to the Items list only if its Type != ItemTypes.None:

// From LevelData constructor
Items = new List<LevelItem>();
for (int i = 0; i < 200; i++)
{
    LevelItem item = new LevelItem(reader);
    if (item.Type != ItemTypes.None)
        Items.Add(item);
}
⚠

The maximum number of active items per level is 200. If you add a 201st item, it will exist in the Items list but will be silently dropped on save (the loop only writes Items.Count records, then zero-fills the rest — but only up to 200 total slots). Always check Items.Count < 200 before adding.

Rendering an item:

// From objectPanel_Paint / tilePanel_Paint
if (!LevelData.TileImages.ContainsKey(item.ArtFile)) continue; // ArtFile=None or unknown
Sprite[] sprites = LevelData.TileImages[item.ArtFile];
if (item.Tile >= sprites.Length) continue;                     // out-of-range Tile index
gfx.DrawSprite(sprites[item.Tile], item.PointA - new Size(scrollX, scrollY));

In BlupiEdit, items are always drawn at PointA. The PointB and movement fields are stored and round-trip correctly, but the editor does not visualise the movement path or the B endpoint.
