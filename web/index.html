About the Game

Speedy Blupi II (released as Eggbert 2 in some regions) is a 2D platformer developed and published by Epsitec SA in 1997. The player controls Blupi — a small yellow oval character — through dozens of levels, collecting eggs and avoiding enemies such as bombs, helicopters, and bulldozers. The game was notable for its colourful pixel art and tight level design built around a 100×100 tile grid.

The game world is divided into World levels (the original campaign) and up to 8 User level sets, each containing up to 20 custom levels. All levels are stored as binary .blp files in the game's data/ folder. Tile graphics and sprite metadata are embedded directly in the game executable (BLUPI.EXE) at fixed binary offsets, rather than in separate asset files.

BlupiEdit was created to let fans and modders explore, view, and eventually edit these level files. Because the format was never publicly documented, all structural knowledge — byte offsets, tile counts, item field semantics — was obtained by reverse engineering the original game binary. The editor reads graphics from BLUPI.EXE at startup; the executable itself is never modified.

The openeggbert open-source project preserves Eggbert 2 for modern platforms and maintains full compatibility with the original .blp file format. For a deeper dive into the game's history and structure, see the Game Context reference page.

What is BlupiEdit?

BlupiEdit is a level editor for the classic platformer Speedy Blupi II (known as Eggbert 2 in some regions). It allows you to load, view, and edit level files (.blp) that ship with the original 1997 game.

The project is written in C# as a Windows Forms application targeting .NET. It works directly with binary data from the original game executable (BLUPI.EXE) — extracting tile graphics and sprite metadata without requiring any modification to the game itself.

ℹ

BlupiEdit is a reverse-engineered tool. All documentation of the .blp format and EXE offsets was obtained by analysing the original game binary.

Quick Start

Step 1 — Open the game

  1. Launch BlupiEdit.exe
  2. Choose File → Open from the menu
  3. Navigate to your Speedy Blupi II directory and select BLUPI.EXE
  4. BlupiEdit extracts all tile graphics and enables the Change Level menu item
⚠

The EXE file is never modified — graphic extraction is a read-only operation.

You can also pass the EXE path as a command-line argument to skip the Open dialog:

BlupiEdit.exe "C:\Games\SpeedyBlupiII\BLUPI.EXE"

Step 2 — Browse and open a level

  1. Choose Level → Change Level
  2. Select a level set in the left list (World or User 1–8)
  3. Pick a level from the level list — a miniature preview renders on the right
  4. Click Open

Navigating the editor

  • Tile Panel (left canvas) — shows the full 100×100 tile grid with background and scrollbars
  • Object Panel (right canvas) — shows interactive game objects; click to select
  • Use the scroll bars beneath each panel to pan around the 6400×6400-pixel world
  • Clicking an object in the Object Panel selects it and shows its properties in the Property Grid

Step 3 — Save the level

  • File → Save — overwrites the current .blp file in place
  • File → Save As — writes to a different slot (World XXX or User X Design XXX)
⚠

Always keep backups! Overwriting original game levels is irreversible.

On close, BlupiEdit will ask whether you want to save unsaved changes.

Features

  • Game EXE loading — automatic tile graphic extraction from the Speedy Blupi II executable at fixed binary offsets
  • Level browser — lists all available levels (World + User 1–8 sets) with a live thumbnail preview
  • Tile Panel — renders the full 100×100 tile grid with parallax background and efficient culling
  • Object Panel — visualises and allows clicking on game objects; selected item is highlighted in yellow
  • Property Grid — displays properties of the selected object (LevelItem) or the whole level (LevelViewModel)
  • TileList control — custom scrollable tile picker with keyboard navigation and drag support
  • Save / Save As — write levels back to original or new slots
  • Cross-platform paths — case-insensitive file lookup for Linux/Mono compatibility
  • Command-line support — pass EXE path as argument to open directly
  • Safe-exit prompt — asks to save on window close when a level is open

Command-Line Usage

BlupiEdit accepts the path to BLUPI.EXE as an optional command-line argument. Passing it skips the File → Open dialog and loads tile graphics immediately on startup.

Windows

# Absolute path (most common)
BlupiEdit.exe "C:\Games\SpeedyBlupiII\BLUPI.EXE"

# Relative path from the current directory
BlupiEdit.exe ..\SpeedyBlupiII\BLUPI.EXE

Linux (Mono)

# Absolute path
mono BlupiEdit.exe /home/user/games/SpeedyBlupiII/BLUPI.EXE

# Relative path
mono BlupiEdit.exe ../SpeedyBlupiII/BLUPI.EXE
⚠

On Linux, file path lookup is case-insensitive within each directory component (BlupiEdit uses FindPathCaseInsensitive), but the directory itself must exist. If BLUPI.EXE is not found or is not a valid Speedy Blupi II executable, LoadGame() throws and the Change Level menu item remains greyed out.

Known Limitations

  • Most level properties in the PropertyGrid are read-only — in-place editing of tile data is not yet implemented
  • Cannot add or delete objects — only inspection of existing objects is possible
  • Tile painting (placing tiles in the grid) is not implemented
  • Supports only Speedy Blupi II — Speedy Blupi I has different EXE offsets
  • Maximum of 200 objects per level (fixed by the .blp format)
  • Maximum of 8 user collections, each with up to 20 levels
  • Linux support via Mono is functional but WinForms styling may differ from Windows
  • The Properties tab is shown in the UI mockup (including the ABDir field) but is not implemented — clicking the Properties tab has no effect in the current revision. The tab exists as a placeholder for a planned feature that was never completed.
  • Several LevelItem fields (field_A, field_24–field_28, field_2E, PointC) are read and round-tripped on save but their purpose is not fully reverse-engineered. The ABDir label visible in the Objects tab PropertyGrid refers to one of these fields.
