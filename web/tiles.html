Tiles & Sprites

How BlupiEdit extracts, stores, and renders tile graphics from the Speedy Blupi II game files.

Overview

Speedy Blupi II stores its graphics as large bitmap files (.blp extension — same extension as level files, but these are standard Windows BMP). Individual tile frames are specified by a table of rectangle + offset descriptors embedded in the game executable (BLUPI.EXE). BlupiEdit reads these tables at hard-coded byte offsets and uses them to extract individual sprite bitmaps from the sprite sheets.

BLUPI.EXE  (tile metadata embedded at fixed byte offsets)
    ├── int16 count + TileInfo[] at 0x862F0  → blupi000.blp (Blupi sprite sheet)
    ├── int16 count + TileInfo[] at 0x872B8  → object.blp   (environment tiles)
    ├── int16 count + TileInfo[] at 0x88768  → element.blp  (element tiles)
    └── int16 count + TileInfo[] at 0x894F8  → explo.blp    (explosion frames)

Sprite sheet files  (relative to game EXE)
    IMAGE16/ or IMAGE08/
    ├── blupi000.blp  ─── character animation sheet
    ├── blupi001.blp  ─── character variant 1
    ├── blupi002.blp  ─── character variant 2
    ├── blupi003.blp  ─── character variant 3
    ├── object.blp    ─── environment tile sheet (used for the 100×100 grid)
    ├── element.blp   ─── element sheet (interactive objects)
    ├── explo.blp     ─── explosion frames
    └── decor{N}.blp  ─── background images (NOT cut into sprites; tiled directly)

At startup (LoadGame()):

  1. BlupiEdit opens BLUPI.EXE and reads the four TileInfo arrays at the hard-coded offsets.
  2. For each sprite sheet, it opens the BMP, applies chroma-key transparency, then clones one sub-rectangle per TileInfo record into a Sprite object.
  3. The source BMP sheet is disposed immediately after all frames are cut from it — only the individual sprite bitmaps are kept in memory.
  4. All sprite arrays are stored in LevelData.TileImages, a static dictionary that lives for the entire application session.

TileTypes Enum

TileTypes : ushort serves two roles: the key in the TileImages dictionary, and the value of the ArtFile field in LevelItem. It identifies which sprite sheet a given item or tile uses.

ℹ

All four Blupi variants (Blupi000–Blupi003) share the same BlupiTiles metadata array read from 0x862F0. Only the source BMP differs. This means all four sheets have the same number of frames and identical frame dimensions — the metadata describes the universal frame layout, and the art varies between sheets.

TileInfo Structure

File: BlupiEdit/LevelData.cs

TileInfo describes one sprite frame: the rectangle to cut from the source bitmap and the draw offset to apply at render time. Each record is exactly 12 bytes (6 × int16).

PropertyCLR TypeBytesDescription
Location Rectangle 8 B (4 × int16) Source crop rectangle in the sprite sheet. Not stored contiguously: X and Y are at bytes 0–3; Width and Height are at bytes 8–11 (interleaved with Offset). Assembled from two separate reads.
Offset Point 4 B (2 × int16) Draw offset applied when rendering. The sprite is drawn at worldPos + Offset rather than exactly at worldPos. Allows the sprite to extend beyond the tile grid square.

Binary Layout (12 bytes per record)

The fields are stored in this exact order in the EXE — note that Location.X and Location.Y come before Offset, and then Location.Width and Location.Height follow after. The Rectangle is built from two separate reads with Offset in between.

BytesFieldCLR typeNotes
0–1Location.Xint16 LELeft edge of source rectangle in sprite sheet
2–3Location.Yint16 LETop edge of source rectangle in sprite sheet
4–5Offset.Xint16 LEHorizontal draw offset (added to world X before drawing)
6–7Offset.Yint16 LEVertical draw offset (added to world Y before drawing)
8–9Location.Widthint16 LEWidth of source rectangle
10–11Location.Heightint16 LEHeight of source rectangle

Constructor source:

public TileInfo(BinaryReader reader)
{
    Point loc = new Point(reader.ReadInt16(), reader.ReadInt16()); // bytes 0–3: X, Y
    Offset   = new Point(reader.ReadInt16(), reader.ReadInt16()); // bytes 4–7: OffX, OffY
    Location = new Rectangle(loc, new Size(
        reader.ReadInt16(),  // bytes 8–9: Width
        reader.ReadInt16()   // bytes 10–11: Height
    ));
}

// Each array in the EXE is prefixed by a 2-byte count
public static TileInfo[] Read(Stream stream)
{
    BinaryReader reader = new BinaryReader(stream);
    TileInfo[] result = new TileInfo[reader.ReadInt16()]; // int16 count at array start
    for (int i = 0; i < result.Length; i++)
        result[i] = new TileInfo(reader);
    return result;
}
ℹ

Each tile array in the EXE is prefixed by an int16 frame count. Seeking to the hard-coded EXE offset puts the stream at this count. TileInfo.Read() reads the count, then reads exactly that many 12-byte records consecutively.

Sprite Structure

File: BlupiEdit/LevelData.cs

Sprite is a struct (value type) that pairs a Bitmap with its draw offset. Each Sprite is created once during LoadGame() by cloning one sub-rectangle from the full sprite sheet bitmap.

MemberTypeDescription
ImageBitmapThe cropped sprite bitmap. Owns its pixel data — allocated by bmp.Clone().
OffsetPointDraw offset added to the world position before DrawImage.
X / Yint { get; set; }Shortcut accessors for Offset.X / Offset.Y.
Width / Heightint { get; }Delegates to Image.Width / Image.Height.
SizeSize { get; }Image.Size.
Left / Topint { get; }Same as Offset.X / Offset.Y.
Rightint { get; }Offset.X + Image.Width.
Bottomint { get; }Offset.Y + Image.Height.
BoundsRectangle { get; }new Rectangle(Offset, Size).
 
public struct Sprite
{
    public Point  Offset;
    public Bitmap Image;

    public Sprite(Bitmap spr, Point off) { Image = spr; Offset = off; }
    public Sprite(Sprite sprite) { Image = (Bitmap)sprite.Image.Clone(); Offset = sprite.Offset; }
}
⚠

Sprite is a struct and copies by value, but Bitmap is a reference type. Copying a Sprite copies the reference to the same bitmap — both copies share the same pixels. Use the copy constructor new Sprite(sprite) only when you need an independent bitmap clone.

EXE Graphic Extraction

File: BlupiEdit/LevelData.cs — LevelData.LoadGame()

The complete loading pipeline performs two phases: metadata extraction from the EXE, then bitmap extraction from the sprite sheets.

public static void LoadGame(string filename)
{
    gameBaseDirectory = Path.GetDirectoryName(Path.GetFullPath(filename));

    // ── Phase 1: read TileInfo arrays from hard-coded EXE offsets ──────────
    using (FileStream fs = File.OpenRead(filename))
    {
        fs.Seek(0x862F0, SeekOrigin.Begin);
        BlupiTiles   = TileInfo.Read(fs);   // int16 count + N × 12-byte records
        fs.Seek(0x872B8, SeekOrigin.Begin);
        ObjectTiles  = TileInfo.Read(fs);
        fs.Seek(0x88768, SeekOrigin.Begin);
        ElementTiles = TileInfo.Read(fs);
        fs.Seek(0x894F8, SeekOrigin.Begin);
        ExploTiles   = TileInfo.Read(fs);
    }  // fs closed — EXE no longer needed after this point

    // ── Phase 2: cut sprites from BMP sheets ─────────────────────────────
    TileImages = new Dictionary<TileTypes, Sprite[]>();

    // All 4 Blupi variants share BlupiTiles metadata; each has its own BMP
    List<Sprite> tmp;

    tmp = new List<Sprite>(BlupiTiles.Length);
    using (Bitmap bmp = LoadImage("blupi000"))   // sheet loaded, used, disposed
        foreach (TileInfo t in BlupiTiles)
            tmp.Add(new Sprite(bmp.Clone(t.Location, bmp.PixelFormat), t.Offset));
    TileImages.Add(TileTypes.Blupi000, tmp.ToArray());

    // ... same pattern for blupi001, blupi002, blupi003 ...

    tmp = new List<Sprite>(ObjectTiles.Length);
    using (Bitmap bmp = LoadImage("object"))
        foreach (TileInfo t in ObjectTiles)
            tmp.Add(new Sprite(bmp.Clone(t.Location, bmp.PixelFormat), t.Offset));
    TileImages.Add(TileTypes.Object, tmp.ToArray());

    // ... same for element, explo ...
}
ℹ

Each sprite sheet BMP is opened, all frames are cloned from it with bmp.Clone(rect, pixelFormat), and then the sheet is immediately disposed. Only the individual sprite bitmaps remain in memory — the full sprite sheet is never kept alive after loading. This reduces the working set compared to keeping the full sheets.

Image Directories

BlupiEdit looks for BMP files in two subdirectories relative to BLUPI.EXE:

DirectoryPriorityDescription
IMAGE16/ First (preferred) 16-colour (4-bit) bitmap art — original game art style. Smaller files.
IMAGE08/ Fallback Palette-based / 8-colour variant. Used only if IMAGE16 directory or file is absent. 
public static Bitmap LoadImage(string filename)
{
    string image16 = FindPathCaseInsensitive(GamePath("IMAGE16", filename + ".blp"));
    string image08 = FindPathCaseInsensitive(GamePath("IMAGE08", filename + ".blp"));

    string path = File.Exists(image16) ? image16
                : File.Exists(image08) ? image08
                : throw new FileNotFoundException("Image not found: " + image16);

    Bitmap bmp = new Bitmap(path);
    bmp.MakeTransparent(Color.Blue);  // chroma-key: exact #0000FF → alpha=0
    return bmp;
}
ℹ

Despite the .blp extension, sprite sheets are standard Windows BMP files. The .blp extension is shared with level files — the game and editor distinguish them by directory (IMAGE16/, IMAGE08/ for graphics; data/ for levels).

Memory Model

After LoadGame() completes, the static LevelData.TileImages dictionary holds all sprite data for the entire session:

LevelData.TileImages : Dictionary<TileTypes, Sprite[]>

TileImages[TileTypes.Object]   → Sprite[N]  (N = ObjectTiles.Length)
TileImages[TileTypes.Blupi000] → Sprite[M]  (M = BlupiTiles.Length)
TileImages[TileTypes.Blupi001] → Sprite[M]  (same M, different bitmaps)
TileImages[TileTypes.Blupi002] → Sprite[M]
TileImages[TileTypes.Blupi003] → Sprite[M]
TileImages[TileTypes.Element]  → Sprite[K]
TileImages[TileTypes.Explo]    → Sprite[J]

Each Sprite.Image is an independently owned Bitmap.
Total memory ≈ sum of all individual sprite pixel areas × bytes-per-pixel.

Sprites are never unloaded during normal operation. The dictionary is replaced in full if LoadGame() is called again. Old sprites are abandoned for GC collection (GDI+ bitmaps are unmanaged resources — if this becomes a concern, explicit Dispose() on the old entries would be needed before replacement).

Chroma-Key Transparency

Speedy Blupi II uses pure blue (#0000FF) as the background colour in its sprite sheets. This was a common technique before alpha channels were widely supported in 16-bit graphics hardware.

BlupiEdit calls Bitmap.MakeTransparent(Color.Blue) immediately after loading each BMP, which:

  1. Converts the bitmap internally to 32-bit ARGB format.
  2. Sets alpha = 0 for every pixel whose RGB value is exactly (0, 0, 255).
  3. Leaves all other pixels fully opaque (alpha = 255).

This transparency is preserved when frames are cloned with bmp.Clone() — the resulting sprite bitmaps are also 32-bit ARGB with transparent pixels in place of the blue background.

⚠

Only exact R=0, G=0, B=255 pixels are made transparent. Near-blue pixels that differ by even one channel value remain fully opaque. Speedy Blupi II art was designed without anti-aliasing, so this exact match is reliable — any blue fringing would indicate a non-original or re-encoded BMP.

Rendering Pipeline

Both tilePanel_Paint and objectPanel_Paint follow this sequence on each Paint event:

panel_Paint(sender, PaintEventArgs e)
    │
    ├─ 1. gfx.SetOptions()         // HighSpeed compositing, NearestNeighbor, no AA
    │
    ├─ 2. Draw background (decor)
    │     LoadImage("decor{Background:000}")  // loaded fresh — NOT cached
    │     Tile across panel: origin = (-scrollX/2, -scrollY/2)  [parallax: half speed]
    │     Step: 640 × 480 px
    │
    ├─ 3. Draw tile grid  (tilePanel only)
    │     Compute visible tile range from scroll offsets
    │     For each (tx, ty) in range:
    │         idx = Tiles[tx, ty]          // -1 = empty, skip
    │         DrawSprite(Object[idx], tx*64 - scrollX, ty*64 - scrollY)
    │
    ├─ 4. Draw Blupi start position  (tilePanel only)
    │     sprIdx = StartDirections[0] ? 0 : 1  // 0 = facing right, 1 = facing left
    │     DrawSprite(Blupi000[sprIdx], StartPositions[0] - scroll)
    │
    └─ 5. Draw all items
          For each LevelItem in Items:
              if ArtFile not in TileImages: skip
              sprites = TileImages[ArtFile]
              if Tile >= sprites.Length: skip
              DrawSprite(sprites[Tile], PointA - scroll)
              [objectPanel only: if item == selectedItem, draw yellow outline rectangle]

Tile Grid Rendering

View-frustum culling is applied — only tiles whose screen position is within the panel bounds are processed:

int scrollX = hScrollBar1.Value;
int scrollY = vScrollBar1.Value;

// Clamp visible tile range to [0, LevelSize)
int xStart = Math.Max(scrollX / LevelData.GridSize, 0);
int yStart = Math.Max(scrollY / LevelData.GridSize, 0);
int xEnd   = Math.Min((scrollX + tilePanel.Width)  / LevelData.GridSize + 1, LevelData.LevelSize);
int yEnd   = Math.Min((scrollY + tilePanel.Height) / LevelData.GridSize + 1, LevelData.LevelSize);

for (int ty = yStart; ty < yEnd; ty++)
    for (int tx = xStart; tx < xEnd; tx++)
    {
        short idx = level.Tiles[tx, ty];
        if (idx < 0 || idx >= objSprites.Length) continue;  // -1 = empty
        gfx.DrawSprite(objSprites[idx],
            new Point(tx * LevelData.GridSize - scrollX, ty * LevelData.GridSize - scrollY));
    }

The iteration order is Y-outer / X-inner — one row at a time — matching the visual top-to-bottom, left-to-right rendering. Note that Tiles is stored x-major (column-major) in memory, so level.Tiles[tx, ty] is the correct access pattern (column first, row second).

The DrawSprite extension applies the sprite's offset on top of the grid position:

public static void DrawSprite(this Graphics gfx, Sprite spr, Point point)
{
    // Final screen position = tile grid position + sprite draw offset
    gfx.DrawImage(spr.Image,
        point.X + spr.Offset.X,
        point.Y + spr.Offset.Y,
        spr.Width,
        spr.Height);
}

Background Rendering

Background decor images are tiled across the entire panel. A parallax effect is achieved by scrolling the background at half the speed of the foreground:

using (Bitmap bg = LevelData.LoadImage($"decor{level.Background:000}"))
{
    // Origin is negative so the background is already drawn before pixel 0
    for (int x = -scrollX / 2; x < panel.Width + 640; x += 640)
        for (int y = -scrollY / 2; y < panel.Height + 480; y += 480)
            gfx.DrawImage(bg, x, y, bg.Width, bg.Height);
}  // bg disposed after each repaint

Key details:

  • Background images are assumed to be 640×480 pixels.
  • Tiling starts at -scrollX/2 (not 0) so the seam never appears at the left edge.
  • The extra +640/+480 in the loop bounds ensures the rightmost and bottom tiles are drawn even if partially off-screen.
  • The background BMP is loaded from disk on every repaint — it is not cached between frames. This is a known limitation: on slow storage, it can cause a visible repaint delay.
⚠

The background is reloaded on every Paint call. If you modify the scroll offset rapidly, this reads the background file many times per second. Caching the current background Bitmap and invalidating it only when Background changes would improve performance significantly.

Coordinate System

BlupiEdit uses a pixel-based world coordinate system:

ConceptValueNotes
Tile size64 × 64 pxLevelData.GridSize = 64
Grid size100 × 100 tilesLevelData.LevelSize = 100
World size6400 × 6400 pxLevelData.PixelSize = 6400
Tile → worldworldX = tileX × 64Top-left corner of tile at grid column tileX
World → screenscreenX = worldX − scrollXSubtract scroll offset to get panel-local coordinates
Screen → world (click)worldX = screenX + scrollXUsed in objectPanel_MouseClick hit-test

Item positions (PointA, PointB, PointC, start positions) are all stored and rendered in world pixel coordinates. Tile indices are in tile coordinates. The relationship:

tileX × 64 = world X of tile top-left corner
item.PointA = {worldX, worldY}  in pixels
screenPos  = item.PointA - new Size(scrollX, scrollY)

The hit-test in objectPanel_MouseClick converts the click to world space and then uses squared Euclidean distance with a threshold of GridSize² = 4096 (64 px radius) to find the nearest item:

Point clickWorld = new Point(e.X + scrollX, e.Y + scrollY);
foreach (LevelItem item in level.Items)
{
    int dx = item.PointA.X - clickWorld.X;
    int dy = item.PointA.Y - clickWorld.Y;
    int dist = dx*dx + dy*dy;  // squared distance — no sqrt needed
    if (dist < bestDist && dist < (LevelData.GridSize * LevelData.GridSize))
    {
        best = item;
        bestDist = dist;
    }
}
