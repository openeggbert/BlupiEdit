Tiles & Sprites

How BlupiEdit extracts, stores, and renders tile graphics from the Speedy Blupi II game files.

Overview

Speedy Blupi II stores its graphics as large bitmap files (.blp extension, but really standard BMP format). Individual tile frames are specified by a table of rectangle/offset pairs embedded in the game executable (BLUPI.EXE). BlupiEdit reads these tables at hard-coded offsets and uses them to cut individual sprite bitmaps from the sheets.

BLUPI.EXE
    ├── TileInfo[] at 0x862F0  → blupi000.blp (Blupi sprite sheet 0)
    ├── TileInfo[] at 0x872B8  → object.blp   (environment tiles)
    ├── TileInfo[] at 0x88768  → element.blp  (element tiles)
    └── TileInfo[] at 0x894F8  → explo.blp    (explosion frames)

IMAGE16/ or IMAGE08/
    ├── blupi000.blp  ─── Bitmap sheet; cut by TileInfo → Sprite[]
    ├── blupi001.blp  ─── Blupi variant 1
    ├── blupi002.blp  ─── Blupi variant 2
    ├── blupi003.blp  ─── Blupi variant 3
    ├── object.blp    ─── Environment/tile sheet
    ├── element.blp   ─── Element sheet
    ├── explo.blp     ─── Explosion sheet
    └── decor{N}.blp  ─── Background images (not cut into sprites)

TileTypes Enum

The TileTypes enum serves as a key in the TileImages dictionary and as the ArtFile field in LevelItem.

NameIDSource BMPTileInfo offset in EXEDescription
None 0 — — No art file; used when an item has no graphic
Object 1 object.blp 0x872B8 Environment tiles; used in the 100×100 tile grid
Blupi000 2 blupi000.blp 0x862F0 Main character, animation set 0 (standing, walking right)
Explo 9 explo.blp 0x894F8 Explosion animation frames
Element 10 element.blp 0x88768 Environmental elements, interactive objects
Blupi001 11 blupi001.blp 0x862F0 Main character, animation set 1 (walking left / mirrored)
Blupi002 12 blupi002.blp 0x862F0 Main character, animation set 2 (jumping, climbing)
Blupi003 13 blupi003.blp 0x862F0 Main character, animation set 3 (special actions)
ℹ

All four Blupi sprite variants share the same BlupiTiles metadata (read once from 0x862F0), but each uses a different BMP sheet (blupi000–003). The offset array defines the same frame layout for all variants.

TileInfo Structure

File: BlupiEdit/LevelData.cs

TileInfo describes a single sprite frame: where to cut it from the source bitmap, and the draw offset to apply when rendering. Each record is 10 bytes.

FieldTypeSizeDescription
Location Rectangle 6 B (3 × int16) Read as: X (int16), Y (int16), then Width (int16) + Height (int16) from a separate read — so really 8 bytes for the rectangle position + size, but stored as Point + Size
Offset Point 4 B (2 × int16) Draw offset applied when rendering: drawX = posX + Offset.X, same for Y

Binary layout of one TileInfo record:

ByteFieldType
0–1Location.Xint16
2–3Location.Yint16
4–5Offset.Xint16
6–7Offset.Yint16
8–9Location.Widthint16
10–11Location.Heightint16
 
public TileInfo(BinaryReader reader)
{
    Point loc = new Point(reader.ReadInt16(), reader.ReadInt16()); // X, Y
    Offset   = new Point(reader.ReadInt16(), reader.ReadInt16()); // drawOffX, drawOffY
    Location = new Rectangle(loc, new Size(
        reader.ReadInt16(),  // Width
        reader.ReadInt16()   // Height
    ));
}

// An array starts with a count (int16) followed by that many records
public static TileInfo[] Read(Stream stream)
{
    BinaryReader reader = new BinaryReader(stream);
    TileInfo[] result = new TileInfo[reader.ReadInt16()]; // count
    for (int i = 0; i < result.Length; i++)
        result[i] = new TileInfo(reader);
    return result;
}

Sprite Structure

File: BlupiEdit/LevelData.cs

Sprite is a value type (struct) that pairs a Bitmap with its draw offset. It is created once during LoadGame() by cloning a rectangle from the source sheet.

MemberTypeDescription
ImageBitmapThe cropped sprite bitmap (owns its pixel data)
OffsetPointDraw offset: added to the world position before drawing
X / YintShortcut accessors for Offset.X / Offset.Y
Width / HeightintDelegates to Image.Width / Image.Height
SizeSizeImage.Size
Left / TopintEquals Offset.X / Offset.Y
RightintOffset.X + Image.Width
BottomintOffset.Y + Image.Height
BoundsRectangleRectangle(Offset, Size)
 
public struct Sprite
{
    public Point  Offset;
    public Bitmap Image;

    public Sprite(Bitmap spr, Point off) { Image = spr; Offset = off; }
    public Sprite(Sprite sprite) { Image = (Bitmap)sprite.Image.Clone(); Offset = sprite.Offset; }
}
⚠

Sprite is a struct, so it is copied by value. However, Bitmap is a reference type — copying a Sprite does NOT deep-copy the bitmap. Use the copy constructor new Sprite(sprite) when you need an independent copy.

EXE Graphic Extraction

The complete loading pipeline in LevelData.LoadGame():

using (FileStream fs = File.OpenRead(filename))
{
    // Step 1: Read TileInfo metadata from hard-coded EXE offsets
    fs.Seek(0x862F0, SeekOrigin.Begin);
    BlupiTiles   = TileInfo.Read(fs);    // count + records
    fs.Seek(0x872B8, SeekOrigin.Begin);
    ObjectTiles  = TileInfo.Read(fs);
    fs.Seek(0x88768, SeekOrigin.Begin);
    ElementTiles = TileInfo.Read(fs);
    fs.Seek(0x894F8, SeekOrigin.Begin);
    ExploTiles   = TileInfo.Read(fs);
}  // fs closed here

// Step 2: For each tile type, load the BMP sheet and clone individual frames
TileImages = new Dictionary<TileTypes, Sprite[]>();

// Blupi variants reuse BlupiTiles metadata, different BMP each time
foreach (var (typeName, tileInfo) in new[] {
    ("blupi000", BlupiTiles,  TileTypes.Blupi000),
    ("blupi001", BlupiTiles,  TileTypes.Blupi001),
    ("blupi002", BlupiTiles,  TileTypes.Blupi002),
    ("blupi003", BlupiTiles,  TileTypes.Blupi003),
    ("object",   ObjectTiles,  TileTypes.Object),
    ("element",  ElementTiles, TileTypes.Element),
    ("explo",    ExploTiles,   TileTypes.Explo),
})
{
    var sprites = new List<Sprite>(tileInfo.Length);
    using (Bitmap bmp = LoadImage(typeName))  // disposed after each loop
        foreach (TileInfo t in tileInfo)
            sprites.Add(new Sprite(bmp.Clone(t.Location, bmp.PixelFormat), t.Offset));
    TileImages.Add(type, sprites.ToArray());
}

Image Directories

BlupiEdit searches for BMP files in two directories relative to the game EXE:

DirectoryPriorityDescription
IMAGE16/ First (preferred) 16-colour (4-bit) bitmap variants — smaller files, original art style
IMAGE08/ Fallback 8-colour (3-bit) or palette-based variants — used when IMAGE16 is absent 
public static Bitmap LoadImage(string filename)
{
    string image16 = FindPathCaseInsensitive(GamePath("IMAGE16", filename + ".blp"));
    string image08 = FindPathCaseInsensitive(GamePath("IMAGE08", filename + ".blp"));

    string path = File.Exists(image16) ? image16
                : File.Exists(image08) ? image08
                : throw new FileNotFoundException("Image not found");

    Bitmap bmp = new Bitmap(path);
    bmp.MakeTransparent(Color.Blue);  // chroma-key #0000FF → transparent
    return bmp;
}
ℹ

Despite the .blp extension, image files are standard Windows BMP format. The extension is shared with level files — context (directory) determines the file type.

Transparency — Chroma Key

Speedy Blupi II uses pure blue (#0000FF) as the transparency colour. This was a common technique before alpha channels were widely supported — the game's own renderer replaced that colour with the background.

BlupiEdit calls Bitmap.MakeTransparent(Color.Blue) which:

  1. Converts the bitmap to 32-bit ARGB format internally
  2. Sets the alpha channel to 0 for every pixel exactly matching Color.Blue
  3. Leaves all other pixels fully opaque
⚠

Only exact #0000FF matches are made transparent. Pixels that are nearly-blue but not exactly R=0, G=0, B=255 remain opaque. This can cause visible blue fringing around sprites if the original art used anti-aliasing (it generally does not).

Rendering Pipeline

The full rendering flow for one panel repaint:

panel_Paint(sender, PaintEventArgs e)
    │
    ├── gfx.SetOptions()           // HighSpeed, NearestNeighbor, no AA
    │
    ├── Draw background (decor)
    │   └── LoadImage("decor{N:000}")   // loaded fresh each repaint
    │       └── Tile across panel at half scroll speed (parallax)
    │
    ├── Draw tile grid             // tilePanel only
    │   └── for visible (x,y) range:
    │       └── DrawSprite(TileImages[Object][Tiles[x,y]], screenPos)
    │
    ├── Draw Blupi start position  // tilePanel only
    │   └── DrawSprite(TileImages[Blupi000][directionIndex], startPos)
    │
    └── Draw items
        └── for each LevelItem:
            └── DrawSprite(TileImages[item.ArtFile][item.Tile], item.PointA - scroll)
⚠

The background image (decorN.blp) is loaded fresh from disk on every repaint — it is not cached. For large or slow storage, this can cause visible repaints. A future optimisation would cache the current background bitmap.

Tile Grid Rendering

Only the visible tile range is drawn (view-frustum culling):

int xStart = Math.Max(scrollX / 64, 0);
int yStart = Math.Max(scrollY / 64, 0);
int xEnd   = Math.Min((scrollX + panelW) / 64 + 1, 100);
int yEnd   = Math.Min((scrollY + panelH) / 64 + 1, 100);

for (int ty = yStart; ty < yEnd; ty++)
    for (int tx = xStart; tx < xEnd; tx++)
    {
        short idx = level.Tiles[tx, ty];
        if (idx < 0 || idx >= objSprites.Length) continue;  // -1 = empty
        gfx.DrawSprite(objSprites[idx],
            new Point(tx * 64 - scrollX, ty * 64 - scrollY));
    }

The DrawSprite extension applies the sprite offset:

public static void DrawSprite(this Graphics gfx, Sprite spr, Point point)
{
    gfx.DrawImage(spr.Image,
        point.X + spr.Offset.X,
        point.Y + spr.Offset.Y,
        spr.Width,
        spr.Height);
}

Background Rendering

The background decor images are tiled across the panel. A parallax effect is achieved by scrolling the background at half the speed of the foreground:

using (Bitmap bg = LevelData.LoadImage($"decor{level.Background:000}"))
{
    // Background scrolls at half speed → parallax effect
    for (int x = -scrollX / 2; x < panel.Width + 640; x += 640)
        for (int y = -scrollY / 2; y < panel.Height + 480; y += 480)
            gfx.DrawImage(bg, x, y, bg.Width, bg.Height);
}  // bg disposed after each paint

Background tiles are assumed to be 640×480 pixels. The tiling starts before position 0 (at -scrollX/2) so the seam is never visible.
