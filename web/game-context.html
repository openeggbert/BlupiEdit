Game Context

This page provides background on Speedy Blupi II (Eggbert 2) — the game that BlupiEdit targets — covering its history, world structure, and file layout.

What is Speedy Blupi II?

Speedy Blupi II is a 2D tile-based platformer published by Epsitec SA in 1997. It is known under two titles:

TitleRegion
Speedy Blupi IIFrench-speaking markets and original Swiss release
Eggbert 2English-language / international release

The player controls Blupi (called Eggbert in the English version) — a small, yellow, oval-shaped character — through a series of levels collecting eggs, riding platforms, and avoiding enemies. The game was notable for its charming pixel art and a built-in level editor that shipped with the original CD-ROM release.

ℹ

BlupiEdit is an independent, open-source re-implementation of a level editor for the game. It is not affiliated with Epsitec SA. All game assets (BLUPI.EXE, BMP sheets, .blp files) remain the property of Epsitec SA.

Epsitec SA is a Swiss software company that also developed the original Speedy Blupi I (Eggbert) and a range of other educational/entertainment titles. Speedy Blupi II uses a different executable format and EXE offsets than Speedy Blupi I — BlupiEdit supports only Speedy Blupi II.

World Structure

Speedy Blupi II organises its playable content into level sets:

SetSlotsDescription
World~20 levelsThe original campaign levels; shipped with the game; stored in the data/ directory as world<NNN>.blp
User 1–820 levels eachEight slots for custom level collections; stored as user<X>design<NNN>.blp; each set also has an info<X>.blp collection header

Each level is a 100 × 100 tile grid representing a world 6 400 × 6 400 pixels in size (each tile is 64 × 64 pixels). A level also holds up to 200 game objects (items) placed at world pixel coordinates.

The four start positions define where each of the four possible players (co-op mode) spawns. In practice only Player 1 is used in single-player.

Installation Directory Layout

A standard Speedy Blupi II installation has this structure:

SpeedyBlupiII/
├── BLUPI.EXE              # Main executable — contains tile metadata at fixed offsets
├── data/                  # Level files (.blp)
│   ├── world001.blp       # World campaign level 1
│   ├── world002.blp
│   ├── …
│   ├── user1design001.blp # User set 1, level 1
│   ├── info1.blp          # User set 1 header (collection name)
│   └── …
├── IMAGE16/               # High-colour (16-bit) sprite BMP sheets
│   ├── blupi000.bmp       # Player start indicator sprite sheet
│   ├── blupi001.bmp       # Blupi variant 1
│   ├── decor000.bmp       # Background decor image 0
│   └── …
└── IMAGE08/               # 8-bit (256-colour) fallback sprite sheets
    ├── blupi000.bmp
    └── …
ℹ

BlupiEdit tries IMAGE16/ first; if a BMP file is absent there it falls back to IMAGE08/. On Linux both directory names are resolved case-insensitively using FindPathCaseInsensitive.

BlupiEdit and the Game

BlupiEdit interacts with two types of game files:

File / DirectoryBlupiEdit readsBlupiEdit writesPurpose
BLUPI.EXEYes — tile metadata at fixed offsetsNeverSource of TileInfo[] arrays and sprite frame geometry
IMAGE16/*.bmp / IMAGE08/*.bmpYes — sprite sheets for renderingNeverVisual data for all tiles and game objects
data/*.blpYes — loads selected levelYes — File → Save / Save AsLevel binary data (tile grid + items + header)
data/info*.blpYes — reads collection nameNeverUser level set headers shown in the level browser

The workflow is intentionally read-only for the game executable: tile graphics are extracted once at startup and cached in memory. Only level .blp files are ever written.

The openeggbert Open-Source Port

The openeggbert project is an open-source re-implementation of Eggbert 2 for modern platforms. Key facts relevant to BlupiEdit users:

  • The port maintains full format compatibility with the original .blp level files — levels created with BlupiEdit play correctly in the open-source port.
  • The port does not require the original BLUPI.EXE; it bundles its own open-source assets. BlupiEdit still requires the original EXE for tile graphics.
  • Both BlupiEdit and the openeggbert port are hosted in the openeggbert GitHub organisation.
  • The open-source port may expose new format fields or extend the .blp schema in future versions — such extensions would not be readable by the original game but would be documented in the BLP Format reference.
